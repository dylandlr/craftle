# Craftle: first two LLM cognition conditions

The manual **Real LLM Minecraft experiment** workflow now offers two treatments. These run **separately in isolated Minecraft episodes**, not simultaneously:

| Preset | Agent ID | Foveal camera | Self-location visit grid | Unverified belief graph |
|---|---|---|---|---|
| LLM baseline | agent_001 | off | off | off |
| LLM augmented | agent_008 | on | on | on |

Both have identical movement/crafting tools, observation boundaries and general system prompt. The map stores only coarse self-position visit counts, not world blocks. The knowledge graph consists of agent-authored hypotheses labeled unverified. The foveal view is a central crop of the same RGB frame.

**Scientific caution:** these are two treatment configurations, not two trained models, and not yet evidence that the augmented architecture performs better. Their full 2^3 factorial family remains generated by scripts/make-config.js for later ablations.

**TAMU connection:** Workflow environment secrets use `TAMU_API_KEY` and `TAMU_CF_COOKIE`. No credential values are stored in code. Gateway URL and vision model must be confirmed to work on the approved network; a cookie alone does not establish access. The client only permits TAMU cookie transmission to chat-api.tamu.ai. If the TAMU gateway is VPN-restricted, connecting a **personal machine's VPN does not give a GitHub-hosted runner VPN access**. Use a permitted VPN-connected self-hosted runner with `self-hosted`, `linux`, `x64`, `tamu-vpn` labels, or run Craftle locally with the required environment variables. Never bypass access controls.

Compare the two conditions on the same Minecraft version/seed, with fresh memory for each episode. Record images, decision counts, physical displacement, deaths, meaningful inventory gains and goals; evaluate independently verified milestones rather than the LLM's self-claims.
